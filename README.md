# Отчёт по лидам Битрикс24 → Telegram

Скрипт присылает в Telegram-группу ежедневную сводку: сколько лидов создано
за день в выбранных статусах, с разбивкой по UTM-источникам и статусам.
Нужен только Python 3.8+ — внешних зависимостей нет.

Пример сообщения:

```
📊 Отчёт по лидам за 13.08.2026

По источникам (UTM_SOURCE):
• yandex-direct: 14
• vk-ads: 6
• google: 3

По статусам:
• Не обработан: 17
• В работе: 6

Итого за день: 24
```

## Как это работает без вашего участия

Скрипт не «висит в памяти» — его будит планировщик (launchd, cron или
GitHub Actions) каждые 15 минут, а дальше скрипт сам решает, что делать:

- **Не время** (ещё не 9:00) или **отчёт уже отправлен** — тихо завершается.
  Что отправлено, он помнит в `state.json` рядом со скриптом.
- **Пора** — собирает отчёт и отправляет. Если интернета не было — уйдёт
  со следующим запуском через 15 минут, без вашего участия.
- **Сломалось** (Битрикс недоступен, ошибка конфига) — в группу приходит
  предупреждение ⚠️ с причиной (не чаще раза в 2 часа), детали — в `report.log`.
- **Компьютер простаивал** — при первом запуске отправятся все пропущенные
  дни, до `max_catchup_days` (по умолчанию 7) отчётов подряд.

## Установка

1. **Вебхук Битрикс24.** В портале: *Разработчикам → Другое → Входящий вебхук*,
   выдайте право **CRM (crm)** и скопируйте URL вида
   `https://вашпортал.bitrix24.ru/rest/1/xxxxxxxx`.

2. **Бот Telegram.** Создайте через [@BotFather](https://t.me/BotFather) (`/newbot`),
   скопируйте токен.

3. **Группа.** Добавьте бота в группу и сделайте его **администратором**,
   затем напишите в группу любое сообщение и узнайте chat_id:

   ```bash
   python3 get_chat_id.py <ТОКЕН_БОТА>
   ```

   Нужен id группы — отрицательное число (`-100…`).

4. **Конфиг:**

   ```bash
   cp config.example.json config.json
   ```

   | Поле | Что указать |
   |---|---|
   | `bitrix_webhook` | URL вебхука из шага 1 |
   | `telegram_token` | токен бота из шага 2 |
   | `telegram_chat_id` | id группы из шага 3 |
   | `period` | `yesterday` (отчёт за вчера) или `today` (за сегодня) |
   | `send_hour` | во сколько отправлять (час, локальное время машины) |
   | `statuses` | ID статусов лида; пустой список `[]` = все статусы |
   | `utm_sources` | значения `UTM_SOURCE` для разбивки; `[]` = без разбивки |
   | `breakdown_by_status` | `true`/`false` — блок «По статусам» |
   | `max_catchup_days` | сколько пропущенных дней досылать после простоя |

5. **Проверка** (из папки проекта):

   ```bash
   python3 bitrix_report.py --dry-run            # показать отчёт за вчера в консоли
   python3 bitrix_report.py --dry-run --period today
   python3 bitrix_report.py --force              # реально отправить прямо сейчас
   ```

## Где запускать (выберите одно)

### Вариант 1. GitHub Actions — не зависит от вашего компьютера (рекомендую)

Отчёт будет приходить, даже если компьютер выключен: скрипт запускается
в облаке GitHub. Бесплатно (приватный репозиторий, расход ~40 мин/месяц
из 2000 бесплатных).

1. Создайте **приватный** репозиторий на GitHub и загрузите туда содержимое
   этой папки (workflow уже лежит в `.github/workflows/report.yml`).
2. В настройках репозитория *Settings → Secrets and variables → Actions*
   добавьте секреты: `BITRIX_WEBHOOK`, `TELEGRAM_TOKEN`, `TELEGRAM_CHAT_ID`.
   При желании добавьте переменные `STATUSES` и `UTM_SOURCES`
   (через запятую: `NEW,IN_PROCESS` / `yandex,vk`).
3. Во вкладке **Actions** запустите workflow вручную (workflow_dispatch) —
   и дождитесь отчёта в группе. Дальше он будет приходить сам каждое утро.

Время отправки — переменная `BTR_SEND_HOUR` и часовой пояс `TZ` в файле
`.github/workflows/report.yml` (по умолчанию 9:00 Москвы). Расписание GitHub
иногда сдвигается на 5–15 минут — это нормально, дублей скрипт не допустит.

### Вариант 2. Ваш Mac (launchd)

Готовый агент лежит в `deploy/bitrix-telegram-report.plist` (пути уже
прописаны под эту папку). Установка:

```bash
mkdir -p ~/Library/LaunchAgents
cp /Users/elasteek/ZCodeProject/bitrix-telegram-report/deploy/bitrix-telegram-report.plist ~/Library/LaunchAgents/
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/bitrix-telegram-report.plist
```

launchd будет запускать скрипт каждые 15 минут и при пробуждении Mac.
Отчёт придёт, как только Mac включится (плюс догон пропущенных дней).
Удалить: `launchctl bootout gui/$(id -u)/bitrix-telegram-report`.

Нюанс: если Mac выключен — отчёт придёт только после включения.

### Вариант 3. Сервер / VPS / мини-ПК (cron)

Всегда включённая машина — самый надёжный вариант:

```
*/15 * * * * /usr/bin/python3 /путь/к/bitrix-telegram-report/bitrix_report.py
```

## Для запуска в CI без файлов (переменные окружения)

Скрипт умеет читать конфиг из переменных: `BTR_BITRIX_WEBHOOK`,
`BTR_TELEGRAM_TOKEN`, `BTR_TELEGRAM_CHAT_ID`, `BTR_SEND_HOUR`,
`BTR_STATUSES` и `BTR_UTM_SOURCES` (списки через запятую), `BTR_PERIOD`,
`BTR_MAX_CATCHUP_DAYS`, `BTR_STATE_FILE`. Используется автоматически,
если `config.json` отсутствует.

## Полезно знать

- **ID статусов**: *CRM → Настройки → Справочники → Статусы лидов* (коды вида
  `NEW`, `IN_PROCESS` или `UC_XXXXXXXX`), либо откройте в браузере
  `https://вашпортал.bitrix24.ru/rest/1/КОД_ВЕБХУКА/crm.status.list?ENTITY_ID=STATUS`.
- **Часовой пояс**: даты в фильтрах Битрикс24 считает в часовом поясе портала,
  а `send_hour` — локальное время машины, где работает скрипт.
- **UTM попадают в лид автоматически**, если посетитель пришёл по ссылке с метками.
- Сумма по источникам может быть меньше итога: часть лидов приходит без UTM.
- Разбивка по другим меткам (`UTM_CAMPAIGN`, `UTM_MEDIUM`…) делается в
  `build_report()` по аналогии с `UTM_SOURCE`.
- `state.json` и `report.log` создаются сами; их можно удалять — скрипт
  посчитает, что отчёты не отправлялись, и вышлет только свежий.
